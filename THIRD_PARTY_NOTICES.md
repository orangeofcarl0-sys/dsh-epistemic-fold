### Why this package vendors rather than depends

Two behaviours require EF to own the base class it extends, and neither is
available by depending on the published package:

1. **The `frameCheckpoint` framing seam.** Every EF policy tier sets
   `framingMode: system-dedup`, which needs an overridable `frameCheckpoint` hook
   on the base engine. No released DSH build provides one: measured against the
   installed `0.2.0-rc.2`, `typeof BasicCompactionEngine.prototype.frameCheckpoint
   === 'undefined'`. Depending on the host package therefore made every tier
   refuse to mount on a real installation.

2. **A byte-identical `mode: basic`.** EF can stand aside and let native Basic
   behaviour run. A subclass of the host engine cannot do this: virtual dispatch
   re-enters EF's own overrides (`compactRegion -> summarize -> frameCheckpoint
   -> compactRegion`), so a pass-through branch reaches EF's invariants rather
   than Basic's. Owning the base class makes the delegation reach code that is
   not EF's.

The vendored copy is a verbatim copy, not a fork with local modifications: the
`frameCheckpoint` seam is already present in the reference checkout this
repository pins, so `src/basic/*` differs from upstream only by the provenance
header and the replaced module doc comment. The drift test asserts that
equality exactly, which is what keeps the maintenance bounded.
